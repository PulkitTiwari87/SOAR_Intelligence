# API

Base path `/api`. The interactive OpenAPI UI is at `/api/docs` (disabled when `SOAR_ENV=production`); the schema is
the source of truth: `/api/openapi.json`. There are 50 operations; this page explains the conventions and groups.

## Authentication

* **Browser**: `POST /api/auth/login` sets an `httpOnly` cookie. State-changing requests must include the header
  `X-Requested-With: soar` (the UI does this).
* **Scripts**: use the `token` returned by login as `Authorization: Bearer <token>`.
* **Machines that only send events / read the blocklist**: header `X-API-Key: <INGEST_API_KEY>`.
* Errors are JSON `{"detail": "..."}` with 401 (no/expired session), 403 (role), 404, 409 (invalid state
  transition), 422 (validation), 429 (login rate limit). Internals are never included in errors.

## Ingest an event

```bash
curl -X POST http://localhost:8000/api/events -H "X-API-Key: $INGEST_API_KEY" -H "Content-Type: application/json" \
  -d '{"source":"syslog","payload":"Mar  6 12:00:01 web-01 sshd[9]: Failed password for root from 91.219.236.222 port 4242 ssh2"}'
```

`source`: `wazuh` (alert JSON), `syslog` (a line, or `{"message","host","timestamp"}`), `network`, `email`
(`{"raw": "<RFC822>"}` or `{"subject","from","reply_to","body","headers"}`), `misp` (attribute → IOC only), `generic`.
Send up to 200 items with `"payloads": [...]`. The response lists, per item: `event_id`, `duplicate`,
`incident_number`, `created_incident`, `correlated_because`, `analyzed`.

## Endpoint groups

| Group | Endpoints | Minimum role |
|---|---|---|
| Auth | `POST /auth/login`, `POST /auth/logout`, `GET /auth/me`, `PUT /auth/profile` | any |
| Users | `GET/POST /users`, `PATCH /users/{id}` | ADMIN |
| Events | `POST /events` (key or `incident:write`), `GET /events` | VIEWER (read) |
| Incidents | `GET /incidents` (filters: `severity status source mitre asset q date_from date_to page limit`), `GET /incidents/stats`, `GET /incidents/{id-or-number}`, `POST …/action` `…/notes` `…/analyze[?llm=true]` `…/report`, `GET …/report/download` `…/blast-radius`, `POST …/actions/run`, `POST …/playbooks/{name}/run` | VIEWER read; SOC_ANALYST write |
| Response | `GET /playbooks`, `GET /playbooks/stats`, `GET /executions[/{id}]`, `POST /executions/{id}/rollback`, `GET /approvals`, `POST /approvals/{id}/decide` (medium: SOC_ANALYST+, high: INCIDENT_RESPONDER+), `GET /blocklist[.txt]`, `DELETE /blocklist/{ip}` | see permissions |
| Threat intel | `GET /intel/iocs`, `POST /intel/enrich` | VIEWER / SOC_ANALYST |
| Assets | `GET /assets`, `POST /assets`, `POST /assets/links`, `GET /assets/graph` | VIEWER read; INCIDENT_RESPONDER write |
| Analysis | `POST /ai/triage` `/ai/phishing` `/ai/anomaly` `/ai/certificate`, `GET /ai/models` `/ai/stats` `/ai/clusters`, `POST /ai/retrain` (ADMIN) | SOC_ANALYST for `POST`, VIEWER for `GET` |
| System | `GET /health`, `GET /ready` (public); `GET /system/health` `/integrations` `/metrics`, `GET /system/audit` (SOC_ANALYST+) | VIEWER |

Report files (PDF) are generated by `POST /incidents/{id}/report` and downloaded from
`GET /incidents/{id}/report/download`; `GET /incidents/reports/all` lists them.
